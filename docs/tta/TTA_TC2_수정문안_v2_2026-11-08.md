```
<시험목표>
초소형위성(ICEYE SAR, PlanetScope 광학) 관측 시점을 예측 원점으로 하여 산출한
수위 및 수체면적 시계열 예측의 정규화 MSE 가 0.38 이하인지 확인
- 대상 지점 : 낙동강 하구 수위관측소 3개소, 예측 원점 24건 (위성 촬영일 8일 × 3개소)
- 예측일수 : D+1, D+7
- 수체면적 : 낙동강 하구 테스트베드, 차기 위성 관측시점 기준

<측정지표>
o 산정식 : MSE(h) = ( MSE_L(h) + MSE_A ) / 2
- MSE_L : 수위 예측 오차의 제곱평균을 지점별 수위 관측범위로 정규화한 값
- MSE_A : 수체면적 예측 오차의 제곱평균을 수체면적 관측범위로 정규화한 값
o 산정 방법
(1) 지상 수위관측소의 수위 시계열과 기상 관측 자료로 수위 예측 모델을 학습한다. 초소형위성
    촬영 연도의 자료는 학습에 사용하지 않는다.
(2) 초소형위성 촬영일을 예측 원점으로 D+1·D+7 수위와 차기 관측시점 수체면적을 예측하고,
    실측 수위 및 탐지 수체면적과 비교한다. 수체면적은 별도 학습 없이 위성 탐지 면적
    계열에서 직접 예측한다.
(3) 정규화한 수위 MSE 와 수체면적 MSE 를 평균하여 종합 MSE 를 산출하고, D+1 및 D+7
    각각 0.38 이하인지 판정한다.
```

## ⑥ 시험 당일 실행 순서 (내부용 — 절차서에는 넣지 않음)

0. **전날 점검** : 저장소가 TC2 커밋 상태인지 — `git status` 가 깨끗하고 `git ls-files backend/app/static/data/index.html` 이 파일을 보여 주며(자료 화면이 커밋에 포함됐다는 뜻) `python3 scripts/eval_iitp_indicator.py -h` 에 `--no-train`, `--restore`, `--station-pause`, `--json-out`, `--text-out` 이 보여야 한다. 클라이언트 PC 의 SSH 터미널(Windows Terminal/OpenSSH, PuTTY 는 Translation = UTF-8)로 들어가 `python3 scripts/eval_iitp_indicator.py --station-pause 0` 을 한 번 돌려(약 30초, 간격 없이 학습까지 전부) 한글 표가 깨지지 않는지 보고 `--restore` 로 되돌린다. 클라이언트 PC 브라우저로 `http://<분석 PC>:18000/data` 가 열리는지 확인한다(ufw 가 켜져 있어 안 열리면 분석 PC 에서 `sudo ufw allow from 172.18.10.0/24 to any port 18000 proto tcp` — 8501 도 쓰면 같은 식으로). 이 접속 확인은 분석 PC 안에서는 할 수 없고 반드시 클라이언트 PC 에서 해야 한다. (`--no-train` 은 내장 2024 산출물 상태에서는 구간 불일치로 멈추므로 리허설에 쓰지 않는다.)
1. **시험대상 기동** : 분석 PC 저장소 디렉터리에서 `docker compose up -d --build watercast` (화면 수정분이 이미지에 들어가도록 반드시 `--build`) → `curl -s localhost:18000/api/v1/health` 가 ok.
2. **절차 (1)** : 클라이언트 PC 브라우저로 `http://<분석 PC>:18000/data` 접속 — 첫 줄에 지역(낙동강 하구)·수위 자료 기간·**수위관측소 6곳(위성 연계 비교 지점 3곳)**·**초소형위성 8장면(ICEYE 4 · PlanetScope 4)**·시험 연도 2020 이 타일로 보이고, 그 아래 촬영일 8개가 칩으로 보인다. 이것이 절차 (1) 의 "대상 지역과 보유 자료(위성영상 8씬, 수위관측소)가 표시되는 것" 이다. 서비스 화면 `http://<분석 PC>:18000/app` 도 같은 지역의 장면 8개와 지점 6개를 보여 주지만, 수치 확인은 /data 가 한눈에 들어온다. 비교 대상은 위성 연계 3개소(구포대교·호포대교·정천교).
   **자료 상세** : 같은 /data 화면에서 — 예측에 실제로 쓰이는 원자료만 보여 주는 읽기 전용 화면(2026-11-10 추가). ① 수위관측소 6지점의 일 수위(전체 기간 / 시험 연도 2020 / 촬영일 전후, 표·그래프·CSV 내려받기·원본 JSON 링크, 촬영일·D+1·D+7 행 표시), ② 촬영일 기준 실측 수위 표(비교 지점 3곳 × 원점 8일 = 24행: 원점·D+1·D+7), ③ 위성 장면 8장의 수체 면적(센서별 공통 격자 면적 = 시계열 비교값, 유효 면적, 장면 범위 면적은 참고, 정답 면적, 탐지 결과 퀵룩) — 머리에 **어디 자료인지**(지역·창 위치 경위도, 영상 센서·기간·원본 파일명, 수체 판정 = 탐지 마스크) 세 줄. 값은 서버 API 응답 그대로이며 학습 상태와 무관하다(학습 전후 같은 값).
3. **절차 (2)~(4)** : 클라이언트 PC 에서 SSH 로 분석 PC 접속 후 저장소 디렉터리에서
   `mkdir -p ~/tta && python3 scripts/eval_iitp_indicator.py --json-out ~/tta/tc2_result.json --text-out ~/tta/tc2_result.txt`
   API 기본값이 분석 PC 로컬이라 옵션 없이도 돈다. 지점 6개를 하나씩 학습하며 지점 사이 20초 간격이 있어 약 2분 30초 걸린다(화면에는 지점마다 `학습 중 …` 과 `완료` 만 찍힌다). JSON 은 계산 상세, TXT 는 화면에 찍힌 표·판정 그대로 — 둘 다 성적서 첨부용. 결과 파일은 저장소 밖(`~/tta/`)에 두어 git 에 섞이지 않게 한다. 실행이 중간에 끊겼으면 그냥 다시 실행한다(서버에서 돌던 지점 학습이 끝나기를 기다린 뒤 첫 지점부터 다시 학습한다 — 다시 약 2분 30초, 결과는 같다).
   **결과 파일을 클라이언트 PC 로** : 실행이 끝나면 화면 마지막에 `scp innonew98@<분석 PC>:/home/innonew98/tta/tc2_result.json innonew98@<분석 PC>:/home/innonew98/tta/tc2_result.txt .` 가 찍힌다. 이 한 줄을 클라이언트 PC 의 터미널(PowerShell·명령 프롬프트·bash 모두 가능, Windows 10 이상은 scp 내장)에 붙여 넣고 비밀번호를 넣으면 두 파일이 클라이언트 PC 의 현재 폴더로 내려온다.
4. **되돌리기** : `python3 scripts/eval_iitp_indicator.py --restore` → `curl -s localhost:18000/api/v1/regions/nakdong_busan | grep -o '"origin":"[a-z]*"'` 가 builtin 이면 끝. 학습 산출물이 남아 있는 동안은 6지점 전부의 선택 모델·전망값(/app·/eval·/simple·시나리오)이 당일 학습 결과로 바뀌어 있으므로(컨테이너는 CPU 추론 전용이라 당일 후보는 고전 모델 5종), 되돌리기 전까지 이 PC 의 전망값을 다른 용도로 쓰지 않는다.
