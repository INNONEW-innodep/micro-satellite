# TTA TC2 절차 (1) — 자료 설명 대본 (내부용, 2026-11-10)

화면: 클라이언트 PC 브라우저 `http://<분석 PC>:18000/data`. 위에서 아래로 보이는 순서대로 말하면 된다.
원칙: 화면에 있는 값만 읽는다. 결과 수치(MSE)는 여기서 말하지 않는다 — 절차 (2)~(4)에서 스크립트가 찍는다.

## 1. 첫 줄 타일 (지역·보유 자료) — 30초

"시험 대상 지역은 낙동강 하구, 부산·김해 구간입니다. 보유 자료는 두 가지입니다.
지상 수위관측소 6곳의 일 수위(국가수자원관리종합정보시스템 WAMIS 개방 자료, 2015년 1월 1일부터 2024년 12월 31일까지)와
초소형위성 영상 8장면(SAR 위성 ICEYE 4장, 광학 위성 PlanetScope 4장, 모두 2020년 2~4월 촬영)입니다.
위성 촬영 연도인 2020년이 시험 연도이고, 이번 시험에는 2015년부터 2020년까지만 씁니다. 2019년까지로 모델을 학습·선택하고 2020년으로 시험합니다. 2021년 이후 자료는 쓰지 않습니다."

촬영일 칩을 가리키며: "이 여덟 날짜가 수위 예측의 원점(기준일)입니다. 각 날짜에서 하루 뒤(D+1)와 일주일 뒤(D+7)를 예측합니다."

## 2. ① 수위 Raw 데이터 — 1분

- 지점 칩: "6곳 중 '위성 연계' 표시가 있는 구포대교·호포대교·정천교 3곳이 위성 수위 산출 위치와 연결된 지점이라 예측 정확도 비교 대상입니다. 나머지 3곳은 학습에만 씁니다."
- 탭: 기본이 '시험 연도 2020'. "2020년 하루 한 값, 단위 m입니다." 전체 기간 탭을 한 번 눌러 "서버에는 2015~2024년 전체가 있고 2020년 구간이 음영으로 표시됩니다"라고 보여 준 뒤 다시 시험 연도로.
- 타일: "자료 일수 366일, 최저·최고, 그리고 관측범위(최고−최저)입니다. 수위 오차는 이 관측범위로 나눠 정규화하므로 지점마다 수위 규모가 달라도 같은 잣대가 됩니다."
- 표: "주황 행이 촬영일(원점), 초록이 D+1, 파랑이 D+7 실측입니다. 값은 WAMIS 원자료 그대로입니다." 필요하면 'CSV 내려받기'로 넘겨 주고, '원본 JSON'은 서버 응답 원문.

## 3. ② 촬영일 기준 실측 수위 — 30초

"비교 지점 3곳 × 촬영일 8개 = 24건입니다. 각 행에 원점 수위, D+1 날짜와 실측, D+7 날짜와 실측이 있습니다. 절차 (3)의 '수위 24건 비교표'에서 예측값과 나란히 놓이는 실측값이 바로 이 값들입니다."

## 4. ③ 수체 면적 Raw 데이터 — 1분

"장면마다 수체 탐지 모델이 물 영역을 뽑고, 그 면적을 셉니다. 센서마다 촬영 범위가 달라서 센서별로 '공통 격자'라는 같은 창을 잡고 모든 날짜를 그 창 안에서 셉니다. 시계열로 비교하는 값은 이 공통 격자 면적입니다."

- 어디 자료인지는 ③ 머리의 **어디 / 영상 / 수체 판정** 세 줄을 그대로 읽는다: "낙동강 하구(부산·김해) 지역입니다. 면적은 관측소 한 지점의 값이 아니라 센서별 공통 격자, 즉 창 전체에서 센 수체 면적입니다. 영상은 ICEYE SAR 4장면(3.2~4.16)과 PlanetScope 광학 4장면(2.18~4.14)의 전처리 영상이고, 수체 탐지 모델(WBMS)이 만든 마스크를 물로 봅니다." 창 위치는 센서 블록 첫 줄 '창 위치'(경위도 환산 — ICEYE 경도 128.769~129.317·위도 34.768~35.380, PlanetScope 경도 128.790~129.102·위도 35.137~35.377). 표 셋째 열이 장면별 **원본 영상 → 탐지 마스크 파일명**(마우스를 올리면 분석 PC 의 전체 경로와 그 장면의 촬영 범위).

| 센서 | 촬영일 | 공통 격자 면적 (km²) |
|---|---|---|
| ICEYE | 3.2 / 3.30 / 4.15 / 4.16 | 40.207 / 36.607 / 36.742 / 39.127 |
| PlanetScope | 2.18 / 3.12 / 3.25 / 4.14 | 30.152 / 28.870 / 30.148 / 30.974 |

- '장면 범위 면적 — 참고' 열: "장면 자기 촬영 범위 안에서 센 값이라 날짜 간 비교에 쓰지 않습니다. 예를 들어 PlanetScope 3월 25일은 촬영 범위가 넓어 65 km²로 나오지만 공통 격자로는 30 km²입니다. 그래서 공통 격자 값을 씁니다."
- '정답(GT) 면적': "사람이 그린 정답 라벨로 센 면적입니다. 탐지가 맞는지 참고하는 값이고, 예측에는 탐지 면적을 씁니다."
- 퀵룩: "청록이 탐지된 물입니다."
- 면적 예측 건수: "센서 안에서 이웃한 촬영일 사이를 예측하므로 센서별 3쌍, 합쳐 6건입니다. 센서가 다르면 창이 달라 서로 비교하지 않습니다."

## 5. 화면에 없는 자료 — 물으면

- 기상: "기상청 ASOS 부산(159) 지점 일 강수·기온, 2015~2024년. 수위 예측 모델 학습의 보조 입력으로 씁니다." (브라우저에서 `http://<분석 PC>:18000/api/v1/regions/nakdong_busan/weather` 를 열면 서버 응답 원문이 보인다. 파일은 저장소 `regions/nakdong_busan/weather/asos_daily.json`)
- 위성 원본·탐지 마스크 파일: 분석 PC `data/incoming/handover/05_l1_pre/`(전처리 원본), `data/wbms_runs/wb/2020/`·`wb_planet/2020/`(탐지 GeoTIFF). ③ 표의 파일명 열이 바로 이 파일들이다. 화면의 '원본 JSON'은 서버 응답, 파일은 분석 PC 에 있다.

## 6. 예상 질문과 답

| 질문 | 답 |
|---|---|
| 자료가 2024년까지인데 시험은? | 서버 보유는 2015~2024. 이번 시험은 2015~2020만 사용(학습·선택 ~2019, 시험 2020). 첫 줄 '이번 시험에 쓰는 구간' 타일. |
| 왜 6곳 중 3곳만 비교하나 | 위성 수위 산출 위치와 연결된 수위계가 3곳(구포·호포·정천). 나머지는 학습에만. |
| 낙동강하구언(내)은 2020년 자료가 13일뿐인데 | 하구언 운영으로 수위가 한 값에 고정된 평탄 구간을 품질관리로 제외(354일). 비교 지점이 아니라 결과에 영향 없음. 화면에 '촬영일 실측 없음(비교 지점 아님)'이라고 적혀 있음. |
| D+1·D+7 실측은 어디서 | ② 표. 촬영일 + 1일·7일의 WAMIS 일 수위 그대로. |
| 정규화 분모가 뭔가 | 시험 연도(2020) 그 지점 관측범위(최고−최저). 오차를 이것으로 나눠 제곱 평균. 면적은 8장면 전체의 관측범위. |
| 센서별 면적이 왜 다른가 | 창(공통 격자)이 센서별로 달라 절대값이 다름. 센서 안에서만 시계열 비교. |
| 수체 면적은 어느 지점 값인가, 어디 영상인가 | 지점 값이 아니라 센서별 창 전체의 수체 면적. ③ 머리 '어디·영상·수체 판정' 세 줄과 센서 블록 '창 위치'(경위도), 표의 원본 영상·탐지 마스크 파일명. |
| 위성 수위는 안 쓰나 | 이번 시험의 수위 비교는 지상 수위계 실측 기준. 위성 수위는 위치 연결 근거(비교 지점 3곳 선정)로만 관여. |

## 7. 하지 말 것

- 결과 수치(MSE)를 미리 말하지 않는다. 스크립트 출력으로 보여 준다.
- 화면에 없는 숫자를 외워 말하지 않는다. 모르면 '원본 JSON'을 연다.
- 학습 단계 소요 시간을 물으면 사실대로 답한다: 지점 하나의 학습 계산은 몇 초이고, 지점 사이에 20초 간격을 두어 진행이 보이게 했다(화면에는 따로 찍히지 않고 계산 상세 JSON 의 train.pause_s·pause_total_s 에 있다). 간격을 계산 시간이라고 말하지 않는다.
