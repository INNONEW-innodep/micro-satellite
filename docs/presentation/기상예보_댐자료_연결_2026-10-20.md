# 기상청 단기예보·댐 운영 자료 연결 (2026-10-20)

2026-10-16 실험(`실시간_시간단위_예보_실험_2026-10-16.md`)의 다음 단계로 구현한 것. 합성값 없음. 서버 배포 상태는 작업로그 §6-25.

## 1. 기상청 단기예보 → 예측기 입력 (실시간 경로)

| 단계 | 구현 |
|---|---|
| 수집 | `POST /api/v1/regions/{id}/weather/forecast-collect` {station_id \| lat,lon} — 공공데이터포털 단기예보 `getVilageFcst`(최근 발표분, +3일). 서버 `KMA_API_KEY`(ASOS 와 같은 키, **단기예보 서비스도 활용신청 필요**) 없으면 422 |
| 집계 | 1시간 PCP("강수없음"·"1mm 미만"·"30.0~50.0mm"·"50.0mm 이상"·"3.2mm") → 날짜별 강수 합, TMP 평균, POP 최대. 격자는 DFS 변환(위경도→nx,ny) |
| 저장 | 지역 사용자 사본 `weather/kma_forecast_daily.json` (schema `watercast.weather.forecast/1`, issued_at). 조회 `GET …/weather/forecast` |
| 시계열 | `RegionRegistry.load_series` 가 관측(ASOS) 마지막 날 **뒤**의 예보 행만 붙이고, 달력 끝 뒤의 날은 `DailySeries.exog_tail` 에 둔다(최대 45일) |
| 예측기 | `ridge_arx_future`(기존)·`ridge_arx_season_future`(신규) 가 자료 끝 원점에서 `future_rain_features` 로 꼬리의 강수를 읽는다. 응답 `future_exog_feed{n_days, issued_at, source, note_ko}` |
| 과거 원점 | 그때의 예보는 보관돼 있지 않아 원점 이후 강수를 0 으로 두고 `note_ko` 로 알린다(실측을 넣으면 완벽 예보 상한이 돼 검증이 왜곡된다) |

기본 후보 풀(`forecasters` 비움)에는 미래 강수 모델이 들어가지 않는다(누수 방지 규칙 유지). 쓰려면 학습·전망 때 id 를 명시한다.

**서버 상태(2026-10-20)**: 서버의 `KMA_API_KEY` 는 ASOS 에는 유효(200)하지만 단기예보 호출은 `403 SERVICE_KEY_IS_NOT_REGISTERED_ERROR` — 공공데이터포털에서 **"기상청_단기예보 ((구)_동네예보) 조회서비스" 활용신청**을 같은 계정으로 하면 된다(코드 수정 불필요). 신청 전까지 `forecast-collect` 는 502 로 사유를 돌려준다.

## 2. 과거 예보로 "그 당시 예보" 재측정 — 아직 못 함(키 필요)

- 공공데이터포털 단기예보 API 는 **최근 발표분만** 준다. 과거 발표 원문은 **기상청 API 허브(apihub.kma.go.kr)** 의 단기예보 자료(`fct_afs_dl`·격자 단기예보)에서
  발표시각(`tmfc`) 구간으로 받을 수 있다(별도 가입·인증키). 정량 강수(PCP)는 2021-12 이후 격자 단기예보에만 있어 **2022~2024 검증 구간**이 대상이다.
- 키를 받으면 할 일: ① 대청·부산 격자의 02시 발표분을 날짜별로 받아 `weather/kma_forecast_history.json`(발표일·대상일·강수) 로 저장
  ② `scripts/eval_realtime_forecast_ideas.py` 의 "완벽 예보" 자리에 실제 예보를 넣어 D+1·3·7 RMSE 를 다시 재고
  ③ 월별 이득 표(2·9월 +, 10~12월 −)가 실제 예보에서도 유지되는지 확인. 기대: 완벽 예보 상한(대청 D+7 120.7→117.6 cm)보다 작은 이득.
- 키 없이 할 수 있는 것은 끝냈다(실시간 피드·배선·응답 표기).

## 3. 댐 운영 일자료 → 계절 분리 예측기

| 단계 | 구현 |
|---|---|
| 수집 | `POST /regions/{id}/dam/collect` {dam_code(7자리), dam_name, start, end} — WAMIS `wkd/mn_dtdata`(무인증) 월 단위 요청, 잘린 응답은 객체 단위로 건짐. 배경 잡 `GET …/dam/collect/jobs/{id}` |
| 저장 | `weather/dam_daily.json` (date, dam_level_m 저수위, inflow_cms 유입, outflow_cms 총방류, power_cms, spillway_cms 여수로, other_cms, intake_cms, rain_mm) + region.json `dam{code,name,daily_file}`. 조회 `GET …/dam` |
| 시계열 | `load_series` 가 외생 `dam_out`·`dam_in`·`dam_level` 로 붙인다(지역의 모든 지점에 같은 댐) |
| 예측기 | `ridge_arx_season` — ridge_arx 특징 + `dam_features`(총방류 1·3·7일 합, 유입 1·3일 합, 저수위 30일 편차; 전부 원점 **이전**) 를 홍수기(6~9월)·비홍수기 두 모델로 적합, 원점의 달로 선택, 표본 부족 시 전체 모델. 기본 후보 풀에 포함 |
| 예보 변형 | `ridge_arx_season_future` — 위 + 원점 이후 3일 강수(예보/실측). 명시했을 때만 후보 |

방류 **계획**(예고)은 공개 API 가 없어 입력하지 않는다(10-16 실험: 예고 방류는 이득 없음, 다음날 실측 유입은 3.1 cm 이득 — 관측 뒤에만 안다).

## 4. 대청댐 측정 (로컬, 같은 분할: 학습 ~2020 · 검증 2021~2023 · 시험 2024, horizon 7)

시험 RMSE cm (검증 RMSE cm, 검증 폴드 평균 직전값 대비 비율). 댐 자료는 WAMIS 2015~2024 3,653행.

| 모델 | D+1 | D+3 | D+7 |
|---|---|---|---|
| 직전값 유지 | 35.3 | 84.5 | 125.0 |
| 현재 선택 모델(analog_knn / analog_knn / ridge_arx) | 33.8 (20.5, 0.89) | 81.1 (49.2, 0.94) | 116.3 (78.5, 0.95) |
| ridge_arx | 32.6 (25.6, 1.83) | 78.6 (50.0, 1.03) | 116.3 (78.5, 0.95) |
| ridge_arx_season — 댐 자료 없이 | 31.3 (24.7, 1.68) | 76.2 (51.3, 1.16) | 111.7 (80.8, 1.05) |
| **ridge_arx_season — 댐 자료 포함** | **28.8** (22.2, 1.36) | **69.3** (49.3, 1.13) | **103.8** (82.3, 1.12) |
| ridge_arx_season_future (완벽 예보 상한) | 27.5 (22.3, 1.39) | 64.2 (45.0, 0.93) | 98.9 (75.1, 0.94) |

읽는 법: 2024년 시험에서는 댐 입력 + 계절 분리가 모든 예측일수에서 가장 낫다(D+7 직전값 대비 −17 %). 그러나 검증 폴드(2021~2023) 평균 비율은 analog_knn 이 더 좋아(2021 폴드에서 계절 모델이 2.4배로 흔들림) **검증 기준 자동 선택은 바뀌지 않는다**. 시험값으로 모델을 고르면 안 되므로 "후보 등록, 자동 선택 불변"이 정확한 상태이고, 서버·저장소 artifact 는 그대로다. 쓰려면 `/simple` ⑤ 에서 `ridge_arx_season` 을 고르거나 학습 요청 `forecasters` 에 넣는다. 발표에 쓸 때는 "시험 연도 1년(2024) 결과"라고 꼬리표를 단다.
