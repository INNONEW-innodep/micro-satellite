# 서버 화면 시연 절차 — 부산 예측 + "새 자료가 들어오면" (2026-10-16)

읽는 사람: 전체회의에서 WATERCAST 서버 화면을 직접 시연할 발표자.
서버는 10/15 배포 상태 그대로이며(2026-10-16 01:20 확인: health ok · 모델 5개 · 화면 5개 200), 아래 절차는 모두 공개 주소에서 실제로 확인한 것이다.

## 2. 시연 A — 부산 지금 자료로 예측 (3분)

`/simple`
1. ① 입력 자료: **낙동강 하구(부산·김해)** 선택 → 타일에 "위성 영상 8장(2020-02-18~04-16) · 수위계 6지점 2015~2024 · 기상 부산 159 · 수위 모델 학습됨" 이 보인다.
2. ② 예측할 값: **수위** → 지점 **호포대교**(또는 구포대교·정천교).
3. ③ 영상 날짜 **2020-04-16** → **7일** → [예측].
4. 결과 카드: 전망선·밴드, "이날 수위 자료 있음 → 전망을 실제와 비교", 모델 이름·2024년 RMSE·검증 RMSE 설명. 면적을 고르면 `level-area-bridge`(수위-면적 곡선)와 평균회귀 두 방식이 나온다.

`/app` ④ 시나리오 (출발일을 자유롭게)
1. 지역 부산 → ④ 탭 → "자료가 있는 기간" 패널(수위계 2015-01-01~2024-12-31, 영상 2020-02~04, 기상 2015~2024).
2. 출발일 **2024-12-01**, 며칠 뒤 **14** → [예측] → 실측(12-02~12-15)과 겹쳐 그린 검증 결과.
3. 출발일을 **2026-09-27** 처럼 자료 밖으로 넣으면 "출발일을 자료 끝 14일 전인 2024-12-17 로 맞췄어요" 안내가 뜬다 — **이게 "지금은 2024년까지밖에 없다"는 장면**이고, 다음 시연 B 의 동기가 된다.

## 3. 시연 B — 새 수위 자료가 들어오면 (5분) ★핵심

사실: WAMIS 개방 API 에 부산 6지점 **2025-01-01~2026-10-16** 일 수위가 이미 있다(2026-10-16 01:15 확인). 서버에서 WAMIS 접속도 된다(서버가 낙동강 유역 관측소 425곳을 받아 옴). 서버 수집 경로는 다른 지역(한강 한강대교, 2025-01 한 달)으로 리허설해 통과했다 — 잡 0.6초, 자료 기간이 2025-01-31 로 늘고 ④ 출발일 상한도 같이 움직였다. **재시작·캐시 문제 없음.**

`/eval`
1. ① 지역: **기존 지역 고르기 → 낙동강 하구**.
2. "수위 자료 수집" 카드: 유역 **낙동강(2)** → 관측소 검색어로 아래 6곳을 찾아 체크(코드로 확인):

   | 지점 | WAMIS 코드 |
   |---|---|
   | 낙동강하구언(내) | 2022696 |
   | 구포대교 | 2022680 |
   | 삼랑진교 | 2022610 |
   | 양산교 | 2022660 |
   | 호포대교 | 2022670 |
   | 정천교 | 2022685 |

3. 기간 **2025-01-01 ~ 2025-12-31** → [수집 시작] → 진행 막대 → 지점별 커버리지 100 % 표시 → 완료.
4. `/app` ④ 로 돌아가 새로고침 → "자료가 있는 기간"이 **2025-12-31** 까지로 늘어난 것을 보여 준다 → 출발일 **2025-12-31**, 14일 → [예측] → "검증 자료 없음(미래)" 전망이 나온다. 이것이 "새 자료가 들어오면 같은 규칙으로 바로 전망이 갱신된다"는 장면이다.
5. (선택, 오늘 기준 전망) 같은 카드에서 **낙동강하구언(내)·양산교·호포대교·정천교 4곳만** 기간 **2026-01-01 ~ 2026-10-16** 으로 한 번 더 수집 → ④ 출발일 **2026-10-16**(자료 끝) → 호포대교 7일 전망 = "오늘 기준 다음 주 전망".

**주의 — 구포대교·삼랑진교는 2026년에 기준면이 바뀌었다.** WAMIS 월평균: 구포대교 2025-12 2.38 m → 2026-01 **12.76 m**(+10.4 m), 삼랑진교 1.66 → **15.43 m**(+13.8 m). 나머지 4곳은 변화 없음(하구언 0.78→0.77, 양산 0.96→0.92, 호포 1.78→1.77, 정천 1.63→1.63). 2026 자료를 그 두 지점에 넣으면 모델이 2015~2024 눈금(2~3 m)으로 학습돼 있어 전망이 엉킨다. **2026 수집은 4곳만** 하고, 구포·삼랑진은 "영점표고 변경 — 오프셋 보정 후 반영 예정"이라고 말하면 된다(플랫폼의 다음 QC 항목).

(선택) 기상도 같이: "기상 자료 수집" 카드 → 부산 159 → 2025~2026 → [수집]. 서버에 기상청 키가 있어 된다(`/api/v1/weather/status` → `server_key_configured: true`, D-1 까지). 안 해도 예측은 돌아간다(기상 항은 0/평년으로 채움) — 시간 없으면 생략.

**재학습은 시연 중에 하지 말 것.** `/eval` 의 [학습 시작]은 13종 전부(신경망 포함)를 다시 돌려 시간이 오래 걸리고 서버에서 측정한 적이 없다. 지금 모델은 새 자료의 최근 60일 창을 그대로 써서 전망하므로 재학습 없이도 결과가 나온다. 재학습은 회의 뒤에.

폴백(WAMIS 가 회의 중 느리거나 끊길 때): 이 저장소 `data/wamis/busan_csv/` 에 지점별 CSV(`date,water_level_m`)를 미리 받아 두었다 — 2025년 6지점, 2026-01-01~10-16 4지점. `/eval` 수위 카드의 **CSV 업로드**로 지점마다 올리면 같은 병합 경로를 탄다.

## 4. 시연 C — 새 위성 장면이 들어오면 (3~5분)

방법 1(안전, 네트워크 무관): `/app` ④ 면적 → "면적 출발 영상" **2020-04-14** 선택 → [예측] → 그 뒤 실제로 들어온 04-15·04-16 장면의 면적(ICEYE 36.74 → 39.13 km²)과 전망을 나란히 보여 준다(두 방식: 평균회귀 vs 수위-면적 다리). "다음 장면이 들어오면 이렇게 대조된다"는 설명.

방법 2(실제 파이프라인 가동, 약 1분): 입구 하나 API 로 기존 ICEYE 장면을 다시 접수한다. 브라우저 업로드는 파일이 1.5 GB(ICEYE 전처리)라 회의장에서는 불가 → 서버에 이미 있는 인수 파일을 **서버 경로**로 등록한다(허용 루트 `/app/data` 안).

```bash
curl -s -X POST https://wc-api.semyeongsoft.com/api/v1/scenes \
  -F region_id=nakdong_busan -F sensor=ICEYE -F image_date=2020-04-16 -F acquisition_time=18:36:30 \
  -F pre_path=/app/data/incoming/handover/05_l1_pre/iceye_pre/2020/20200416/Pre_Busan_ICEYE_20200416T183630.tif \
  -F order_id=DEMO-1016 -F note="전체회의 시연"
# → {"scene_id":"20200416_ICEYE","status_url":...}
curl -s https://wc-api.semyeongsoft.com/api/v1/scenes/20200416_ICEYE | python3 -m json.tool | head -60
```

`/app` ② 처리 현황에서 같은 장면의 6단계(등록 → 수체 탐지 → 면적 → 수위 산출 → 시계열 예측 → 규약 파일·로그)가 차례로 done 이 된다. 서버 실측: 탐지 55 s(컨테이너 49 s, CPU), 면적 3 s, 예측 0.04 s. 수위 산출 단계는 10/03 에는 권한 문제로 실패했지만 10/15 배포에서 고쳐져 대청 10/08·10/09 장면은 통과했다(이 장면만 아직 옛 기록이 남아 있어 재접수하면 갱신된다). 같은 장면이 돌고 있는 동안 다시 보내면 409.

## 5. "위성 데이터 시계열 플랫폼" 혁신성과의 정합 — 솔직한 점검

맞는 것(지금 있는 것)
- **지역 등록형**: `regions/` 레지스트리 7개 지역(부산·대청·금강 본류·한강·낙동강 상류·섬진강·영산강), 사용자 사본이 내장본을 덮는 구조 — 새 지역은 등록만 하면 같은 화면·같은 API.
- **입구 하나 파이프라인**: 장면 1장 → 등록 → 탐지(시립대 WBMS 컨테이너) → 공통 격자 면적 → DEM 수위 → 예측 → 통합 플랫폼 규약 파일(PT000003_…)·JSONL 로그. 주문·작업·알고리즘 ID 연계 파라미터까지.
- **자료 수집 내장**: WAMIS 일 수위(무인증)·기상청 ASOS 수집 잡이 화면에 있고, 수집 즉시 자료 기간·전망 상한이 움직인다(오늘 리허설로 확인).
- **모델 레지스트리**: 예측 어댑터 5종 + 수위 예측기 14종(ridge·AR·Prophet·k-NN·GRU·LSTM·TCN·앙상블 …)을 지점×예측일수마다 자동 선택, 시험 연도 2024 비공개.
- **시나리오 검증**: 자료가 있는 기간을 보여 주고 출발일·예측일수를 골라 실측과 대조, 자료 밖 날짜는 "자료 끝 H일 전"으로 자동 보정.
- **설치 패키지·API 문서**: `dist/watercast-0.2.0-*.tar.gz`, `/docs` 60여 엔드포인트, 연계 기관용 `/easy`.

부족한 것(발표에서 "다음 단계"로 말할 것)
- **자동 인입이 없다**: 새 장면·새 수위는 사람이 올리거나 수집 버튼을 눌러야 한다(스케줄러·폴링·웹훅 없음). 1세부 플랫폼에서 장면이 떨어지면 자동으로 도는 구조가 다음 단계.
- **자료 품질(QC) 규칙이 얇다**: 오늘 발견한 구포·삼랑진 기준면 +10 m 같은 변화를 잡아 주는 검사가 없다 — 영점표고 변경 탐지·오프셋 보정 항목을 추가해야 한다.
- **위성 계열은 희소**: 지역·센서당 4~10장이라 면적 예측은 평균회귀/수위-면적 다리 수준. 학습형 면적 모델은 홍수기·공동실증 장면이 더 쌓여야 한다.
- **재학습은 수동**이고 서버 소요 시간을 재지 않았다. 새 자료 뒤 자동 재평가·재학습 트리거가 없다.
- **보안·인증 없음**(사용자 결정으로 의도된 상태) — 외부 공개 시 필요.

추천 문구: "위성 '관측'과 지상 '예측'을 한 플랫폼에서 지역·모델 등록형으로 운영하고, 새 자료가 들어오면 같은 규칙으로 즉시 재평가된다"를 혁신성으로, 자동 인입·QC·홍수기 표본을 다음 단계로.

## 7. (03시 추가) `/simple` 3판 — 사용자가 정한 흐름 그대로

1. **① 입력 자료**: 지역 칩 → 자료 타일(위성 영상 n장·기간·센서 / 지상 수위계 / 기상 / 수위 모델) → 바로 아래 **판정 상자**: "위성 자료만으로는 시계열 예측이 아직 안 돼요 → 지상 수위계로 예측하고 위성은 검증에 써요 (경로 B)" + 사유(센서당 장면 수, 관측 기간, 홍수기, 라벨·대조 건수, 수위계 유무) + 경로 A 조건. 위성이 충분하면 초록 "경로 A", 수위계도 없으면 주황 "자료 수집 필요".

4. **[예측 시작]** → 결과 카드: 물 영역(영상 날짜일 때만), 수위 전망 — **검증에서 가장 잘 나온 모델 하나**로 보여 주고 카드 위 "모델" 선택에서 13종으로 바꿔 볼 수 있음(자동으로 되돌리기 가능), 면적 전망 — 모델 선택(수위 연동 / 면적 추세 / 직전값 유지).
5. **상세 페이지 카드**: 서비스 화면 `/app`(영상 올리기·시나리오·모델 비교·처리 현황) · 모델 성적표 `/eval`(지점·예측일수별 성적·자료 수집·재학습).

판정은 서버 `GET /regions/{id}/scenarios` 의 `expansion` 을 쓰고, 없으면 화면이 같은 규칙으로 계산한다. 캡처: `docs/presentation/screens/simple_v3_0{1..4}_*.png`(로컬 실자료), `screens/server_v3/`(공개 주소).

### 9-1. (11시) ② '새 영상 올리기' — 접수 규격의 입력 전부
① 영상 정보(센서·촬영일·촬영 시각 UTC) → ② 영상 파일(파일 올리기 / 서버에 있는 파일 경로 — 큰 파일은 경로가 빠름): 전처리 영상(필수) · 3-class 마스크(레이더, 선택 — 없으면 인수 마스크 → 인접 날짜 → 영상 범위 자동) · 수체 마스크(선택, 주면 탐지 생략) · 정답 라벨(선택, 주면 IoU·F1 산출) → ③ 실행 옵션(탐지 실행·면적 전망) → ④ 연계 정보(주문·장면·작업·알고리즘 번호, 산출물 종류, 제품 번호, 메모) → ⑤ 입력 점검(무엇이 들어갔고 무엇이 자동 처리되는지) → [접수하고 탐지 시작] → 6단계 진행 표시 → 끝나면 그 영상이 선택된 채 다음으로. 필수 3개(센서·촬영일·전처리 영상)가 차야 버튼이 켜지고, 탐지를 끄면 수체 마스크가 있어야 한다. 시연용 서버 경로 예: `/app/data/incoming/handover/05_l1_pre/iceye_pre/2020/20200416/Pre_Busan_ICEYE_20200416T183630.tif`(같은 장면 재접수 → 기존 결과 갱신).

### 9-2. (11시 반) ② '있는 영상 고르기' — 단일 선택 + 계열 포함/빼기
출발 영상은 하나만 고른다(그 날짜가 출발일, 그 영상의 물 영역·위성 수위가 결과에 쓰임). 면적 계열은 **출발 영상 + 같은 센서의 이전 영상**이 자동으로 들어가고, 카드마다 배지(출발 영상 / 계열 포함 / 다른 센서·계열 밖 / 출발 뒤·실제 비교용)가 붙는다. 포함 영상은 [빼기]로 계열에서 제외할 수 있다(품질 나쁜 장면용; `POST /scenes/{id}/predict` 의 `exclude_scene_ids`, 응답 `summary.excluded_scene_ids`). 격자 아래 안내줄이 "계열 N장 · 뺀 영상 M장"과 3장 미만 경고를 보여 준다. 결과 요약 칩과 면적 설명에도 계열 구성이 나온다.
