## 2. 실행 순서 (자세한 것은 묶음 안 `배포_실행순서.md`)

```bash
# 사전 확인: docker 24+, docker compose v2, python3, curl, 디스크 2 GB(실탐지 포함 45 GB), 포트 18000/8501/8502
tar -xzf watercast-0.2.0-20261021.tar.gz && cd watercast-0.2.0-20261021
cp .env.example .env && vi .env      # 아래 3절. 포트가 비어 있고 uid 가 1000 이면 그대로 둬도 됨
./install.sh                         # 체크섬 → 이미지 load → 앱 묶음 → 기동 → 스모크 18개  (로그 logs/install_*.log)
./postcheck.sh                       # 배포 후 확인 26개 → 보고서 logs/postcheck_*.txt
```
실패하면 스크립트가 **멈춘 명령·줄·로그 파일·컨테이너 로그 30줄**을 마지막에 찍습니다. 그 로그 파일을 보내 주시면 됩니다.

## 3. 설치 전에 정할 설정 (`.env`)

| 항목 | 기본 | 설명 |
|---|---|---|
| 포트 `WATERCAST_API_PORT`/`UI_PORT`/`PIPE_PORT` | 18000/8501/8502 | 겹치면 변경 |
| `RUN_AS` | 1000:1000 | 묶음을 푼 계정의 `id -u`:`id -g` 와 같게 (탐지 산출물 소유자) |
| `WBMS_GPU` | auto | GPU 있으면 GPU, 없거나 실패하면 CPU 자동 |
| `KMA_API_KEY` | 비움 | **선택** — 기상청 자료(과거 관측·단기예보)를 새로 받을 때만. 없어도 전부 동작 |
| `BACKEND_LIAISON_LOG_URL` 등 연계값 | 비움 | 통합 플랫폼이 배정하면 입력. 비면 로그 전송 안 함 |
| 데이터 위치 | 고정 | 새 위성 영상은 `data/incoming/handover/05_l1_pre/<센서>_pre/<yyyy>/<yyyymmdd>/Pre_*.tif`, 산출은 `backend/data/scenes/…` (따로 경로 지정 없음) |

**우리 API 는 인증(키)이 없습니다.** `http://<서버>:18000/api/v1/...` 를 바로 호출하면 되고 전체 목록은 `http://<서버>:18000/docs` 입니다.

환경(docker/compose/python/디스크) · `.env`·앱 묶음·쓰기 디렉터리·탐지 캐시 · 컨테이너 healthy·포트 응답·docker 소켓 · API health/버전/build 일치·지역 목록·수위 전망·오류 응답 형식·최근 오류·화면 3개·서버 오류 로그 0건 · 스모크 18개. 끝에 `결과: 통과 N · 실패 0` 이면 됩니다.

## 5. 이후 코드만 바뀐 배포

`watercast-app-0.2.0-<빌드>.tar.gz`(+`.sha256`, 약 90 MB)만 보내 드립니다. 이미지는 그대로 두고
```bash
cp watercast-app-0.2.0-<빌드>.tar.gz* app/ && ./update_app.sh app/watercast-app-0.2.0-<빌드>.tar.gz   # 1분
./update_app.sh --rollback   # 문제 시 직전 build 복귀
```
