## 1. 사용자가 정한 규칙 (반드시 지킬 것)

- **커밋·푸시 금지** — 사용자가 결정. `regions/` 등 미추적 파일 다수. `git checkout backend/app/api_docs.py` 금지.
- **보안은 넣지 않는다** — 과제용. 인증·API 키·접근 제한 추가하지 말 것(사용자 명시).
- **기존 기능 유지** — 새 기능은 얹는 방식. Streamlit 화면(ui_next 8501, pipeline_ui 8502)은 손대지 않음.
- 다른 세션의 작업로그 파일은 건드리지 않음. 내 로그는 `작업로그_2026-09-08_…수위예측.md` 뒤에 절을 추가.
- 서버 `.env`(KMA 키) 보존, `authorized_keys` 수정 금지, 서버 재배포는 tar 업로드 + `docker compose build && up -d`.

## 3. 시스템 구조 (지금)

```
영상 1장 ─▶ POST /api/v1/scenes (또는 /easy·/app 화면)
              │ backend/app/pipeline/  6단계: register → detect → area → levels → predict → deliver
              │ 탐지는 API 컨테이너가 docker 소켓으로 wbms:0.13 을 직접 실행 (BACKEND_HOST_ROOT 경로 변환, RUN_AS, GPU auto)
              ▼
         backend/data/scenes/<region>/<scene_id>/  (PT000003_<product_id>.tif · WB_*.tif · quicklook · overlay · area/levels/prediction/status.json)
         GET /api/v1/scenes/{scene_id}  ← 단계별 상태·산출물 URL
기존 API 유지: /regions/* (지역·수위계·장면·면적·수위), /wbms/* (탐지 잡·융합), /predictions/*, /gauge/*
```

- 지역 레지스트리 `regions/<id>/` (내장) + 사용자 사본 `backend/data/regions/<id>/` (사본이 내장을 가림, 위성 자산은 내장 폴백).
- 센서 카탈로그 `backend/app/wbms/catalog.json`: iceye(부산), planet(부산·대청), **umbra**(대청, 컨테이너엔 `iceye` 로 전달·산출 이름 `WB_DCD_ICEYE_*`).
- 연계(통합 플랫폼): `backend/app/wbms/liaison.py`(규약 파일명 `{PT}_{product_id}.tif`), `liaison_log.py`(로그 4종 POST). 환경변수 `BACKEND_LIAISON_LOG_URL/_SYSTEM_CODE/_ALGM_ID` — **수자원공사(1세부)가 줘야 하는 값 3개**(SC/AG 코드, product_id 규칙, 로그 API 주소) 대기 중. 비면 전송 안 함.
