# 화면 개편 설계 — 서비스 화면 / 모델 평가 화면 분리

작성 2026-10-14. 기존 화면(Streamlit ui_next 8501, 데모 8502, /easy)은 그대로 두고, 백엔드(18000)가 직접 서빙하는
정적 단일 페이지 두 개를 얹는다. 외부 의존 없음(vanilla HTML/CSS/JS, CSP self).

## 1. 왜 나누나

지금은 한 화면에 "서비스"와 "모델 실험"이 섞여 있어 처음 보는 사람이 어디를 눌러야 하는지 모른다.
- **서비스 화면 `/app`** — 자료가 들어오면 ① 어디인지 확인 → ② 수체·수위 탐지 → ③ 시각화 → ④ 원하는 모델로 예측. 끝.
- **모델 평가 화면 `/eval`** — 새 지역이 와도 수위 자료(WAMIS)·기상(기상청) 수집 → 학습 → 성능표 → 시험까지 한 줄로.
- 설명·전문가 화면·API 문서는 상단 **도움말 탭**으로 뺀다. `/` 는 `/app` 으로 보낸다.

## 2. 서비스 화면 `/app`

```
[서비스]  [모델 평가 →/eval]  [도움말 ▾ 설명 · 전문가 화면(8501) · 데모(8502) · API 문서(/docs)]

① 자료 넣기 · 위치 확인      ② 탐지 (수체 · 수위)      ③ 시각화      ④ 예측
```

| 단계 | 사용자가 하는 것 | 화면이 보여 주는 것 | 쓰는 API |
|---|---|---|---|
| ① | 지역·센서·날짜 고르고 영상 파일을 놓는다(또는 최근 장면 선택) | **위치 지도**: 지역 경계, 수위 지점(이름), 기존 장면 촬영범위(회색), 새 장면 촬영범위(파란색), "이 영상은 지점 n개를 덮습니다" | `POST /scenes`, `GET /scenes/{id}`(register 단계 뒤), `GET /regions/{id}/geometry` |
| ② | 기다린다 | 탐지·면적·수위 단계 체크리스트, 물 면적, 지점별 위성 수위 | `GET /scenes/{id}` steps |
| ③ | 본다 | 물 영역 오버레이, 면적 시계열(센서별), 위성 수위 시계열(지점별 실측 대조) — 인라인 SVG 차트 | `…/satellite/area-series`, `…/satellite/levels`, `…/satellite/files/…` |
| ④ | 지점·모델·예측일수를 고른다 | 수위 전망 차트(밴드), 면적 전망(장면 마스크 시계열) | `GET /gauge/forecasters`, `GET …/gauge/{station}/forecast?forecaster=&horizon=`, `GET /models`, `POST /scenes/{id}/predict` |

지도는 외부 타일 없이 인라인 SVG(경위도 → 등장방형 투영)로 그린다. 배경은 지역의 최신 퀵룩. "OpenStreetMap 에서 보기" 링크만 외부.

## 3. 모델 평가 화면 `/eval`

```
[서비스 →/app]  [모델 평가]  [도움말 ▾]

준비 상태 패널: 지점 n · 수위 자료 기간 · 기상 자료 기간 · 학습 여부 · 위성 장면 n   ("다음 할 일" 안내)

① 지역 만들기/고르기  ② 수위 자료 수집  ③ 기상 자료 수집  ④ 학습(구간 선택)  ⑤ 성능 평가  ⑥ 시험
```

| 단계 | 하는 것 | API |
|---|---|---|
| ① | 기존 지역 선택 또는 새 지역(id·이름·bbox) 생성 | `GET /regions`, `POST /regions` |
| ② | 유역 고르고 지점 이름으로 검색 → 지점 선택 → 기간 → 수집(배경 잡) 또는 CSV 업로드 | `GET /wamis/stations?basin=&match=`, `POST …/gauge/collect`, `GET …/gauge/collect/jobs/{id}`, `POST …/gauge/{station}/series/file` |
| ③ | ASOS 지점 고르고 기간 → 수집(배경 잡) | `GET /weather/stations`, `POST …/weather/collect`, `GET …/weather/collect/jobs/{id}` |
| ④ | 학습·검증·시험 연도 슬라이더, 후보 예측기 체크 → 학습(배경 잡) | `GET /gauge/forecasters`, `POST …/gauge/train`(async), `GET …/gauge/train/jobs/{id}` |
| ⑤ | 지점×예측일수 표(선택 모델·MSE·RMSE·개선율), 모델 비교 차트, 백테스트 차트, 수체 면적 모델 실험 | `GET …/gauge/evaluation`, `…/forecast/compare`, `…/backtest`, `…/gauge/experiments` |
| ⑥ | 원점 날짜·지점·모델 골라 전망 vs 실측 | `GET …/gauge/{station}/forecast?as_of=&forecaster=` |

## 4. 새로 만드는 백엔드 (계약)

- `GET /api/v1/regions/{id}/geometry` → `{region_id, name, bbox_wgs84:[minlon,minlat,maxlon,maxlat], stations:[{id,name,lat,lon,terrain,satellite_location}], aois:[{loc_id,station_id,polygon_lonlat:[[lon,lat]…],anchor_lonlat}], scenes:[{scene_id,sensor,date,footprint_lonlat,quicklook_url,overlay_url,detection_available,water_area_km2}]}`
- `GET /api/v1/regions/{id}/readiness` → `{gauge:{n_stations,period,n_days}, weather:{available,station,period}, models:{trained,trained_at,split}, satellite:{n_scenes,n_with_masks}, next_steps:[…한국어]}`
- `GET /api/v1/wamis/stations?basin=1..5&match=` → `{basin, items:[{code,name,river,address}]}` (scripts/fetch_wamis_levels.list_basin_stations 재사용)
- `POST /api/v1/regions/{id}/gauge/collect` `{stations:[{id,name,code,terrain}], start, end, min_coverage, async_run}` → 202 `{job_id}`; `GET …/gauge/collect/jobs/{job_id}` → `{status, progress, stations:[{id,n_days,coverage,status,note}], error}` — WAMIS 수집 후 기존 시계열 저장 경로로 병합
- `POST /api/v1/regions/{id}/weather/collect` `{station_id, start, end, async_run}` → 202; `GET …/weather/collect/jobs/{job_id}` — 기상청 ASOS(키 필요) 연도별 수집 → `regions/<id>/weather/asos_daily.json` 사용자 사본 + 매니페스트 갱신
- `POST /api/v1/scenes/{scene_id}/predict` `{model_id, horizon, as_of?}` → 파이프라인 예측 단계만 다시 실행(선택 모델) → `{prediction_id, prediction_url, as_of, summary:{steps:[…], later_frames:[{date,scene_id,water_area_km2}]}}` — `as_of`(2026-10-14 추가)는 시나리오 원점: 그 날짜까지의 프레임만 쓰고 그 뒤 프레임의 실제 면적을 돌려준다
- `GET /api/v1/regions/{id}/scenarios?as_of=&horizon=` (2026-10-14 추가, `backend/app/screens/scenarios.py`) → `{gauge:{period,n_days,stations[]}, weather:{period}, satellite:{scenes[{date,sensor,has_frame,in_gauge_period,area_km2_common_frame}]}, models:{split,horizon_max}, forecast_window:{origin_min,origin_max,horizon_max,verifiable_until}, scenarios:[{kind: scene|test_start|verify|latest, as_of, label_ko, available, observed_days_after, in_sample}], requested:{as_of, available, resolved_as_of, clamped, observed_days_after, target_date, note_ko}}` — ④ 의 '자료가 있는 기간' 패널·시나리오 선택. 영상 날짜가 수위 자료 밖이면 `requested.clamped=true` 와 함께 '자료 끝 H일 전'을 권한다
- `GET …/gauge/{station}/forecast` 응답에 `requested_as_of`·`as_of_clamped`·`data_period`·`observed_days_after`·`origin_note_ko` 추가(2026-10-14). 자료 시작 전 원점은 422

### 4-1. ④ 시나리오 흐름 (2026-10-14)

```
자료가 있는 기간(수위계·기상·위성 영상·학습/검증/시험 시간표)
   → 시나리오 고르기(이 영상 날짜 · 다른 영상 날짜 · 시험 연도 첫날 · 자료 끝 H일 전 · 자료 마지막 날 · 직접)
   → 출발일(원점) ↔ 며칠 뒤까지 ↔ 끝 날짜 (서로 맞춤)
   → "실제 수위와 비교할 수 있는 날 n일 / 표본 내 경고 / 자료 밖 안내"
   → 수위 전망(실측 대조) · 면적 전망(출발 영상 뒤 실제 영상 대조)
```

5. 인수인계 문서

## 6. 하지 않는 것

인증·키 없음(과제용). Streamlit 화면은 손대지 않음(도움말 탭에서 링크). 지도 타일 서버 없음(오프라인 SVG).
