# WATERCAST 배포 실행 순서 — 배포 담당자용 (명령어 순서대로)

대상: 이노뎁 2세부 "위성 수체·수위 탐지 및 시계열 예측" 서비스를 **서버에 설치·확인·교체**하는 담당자.
소스 빌드는 없다. 받은 묶음을 풀고 스크립트 네 개(`install.sh` → `postcheck.sh`, 나중에 `update_app.sh`)만 순서대로 실행한다.
모든 스크립트는 `logs/` 에 로그를 남기고, 실패하면 **어느 단계·명령에서 멈췄는지와 그때 볼 로그**를 화면 마지막에 찍는다.

## 0. 받을 것

| 파일 | 크기 | 용도 |
|---|---|---|
| `watercast-<버전>-<날짜>.tar.gz` | 약 0.5 GB | 기본 묶음 = 런타임 컨테이너 이미지 + 앱 바이너리 + 런타임 데이터 + 스크립트 |
| `watercast-<버전>-<날짜>-detect.tar.gz` | 약 40 GB | (선택) 실탐지 묶음 = wbms 탐지 이미지 11 GB + 모델·전처리 입력. **새 위성 영상을 탐지**하려면 필요 |
| `watercast-app-<버전>-<빌드>.tar.gz` (+ `.sha256`) | 약 0.2 GB | (나중에) 코드만 바뀐 앱 바이너리. 이미지는 그대로 두고 이것만 교체 |

## 1. 사전 확인 (서버에서, 2분)

```bash
docker --version && docker compose version          # docker 24 이상, compose v2
python3 --version && curl --version | head -1       # python3 3.9 이상, curl
docker info >/dev/null && echo "docker 데몬 OK"      # 안 되면: docker 그룹에 넣거나 sudo 로 아래 전부 실행
df -h .                                              # 기본 묶음 2 GB, 실탐지 묶음까지 45 GB 여유
id -u; id -g                                         # .env 의 RUN_AS 에 적을 값 (예: 1000:1000)
for p in 18000 8501 8502; do (ss -ltn 2>/dev/null || netstat -ltn) | grep -q ":$p " && echo "포트 $p 사용 중" || echo "포트 $p 비어 있음"; done
nvidia-smi -L 2>/dev/null || echo "GPU 없음(CPU 로 동작)"   # GPU 는 선택
```

## 2. 설치 (10분 안쪽)

```bash
mkdir -p ~/watercast && cd ~/watercast
tar -xzf /경로/watercast-<버전>-<날짜>.tar.gz
cd watercast-<버전>-<날짜>
cp .env.example .env
vi .env            # 3절 "설정 항목" 참고 — 포트가 비어 있고 uid 가 1000 이면 그대로 둬도 된다
./install.sh       # 1/7 요구사항 → 2/7 체크섬 → 3/7 .env → 4/7 런타임 이미지 load → 5/7 앱 묶음 → 6/7 기동 → 7/7 스모크 18개
```

기대 출력(끝부분):
```
  ✔ 스모크 테스트 18/18 통과
설치 완료  (앱 0.2.0 build 202610211030 (6c594ec))
  API 문서   http://<이 서버>:18000/docs        (인증 없음 — 바로 호출)
  ...
  로그       /.../logs/install_20261021_103000.log
```

실탐지(새 영상 탐지)까지 쓰려면 실탐지 묶음을 **같은 디렉터리 안에** 풀고 다시 설치한다.
```bash
tar -xzf /경로/watercast-<버전>-<날짜>-detect.tar.gz --strip-components=1
./install.sh --with-wbms      # wbms:0.13 11 GB 적재 (10분 이상)
```

## 3. 설정 항목 (`.env`) — 배포 전에 정할 것

| 항목 | 기본 | 언제 바꾸나 |
|---|---|---|
| `WATERCAST_API_PORT` / `WATERCAST_UI_PORT` / `WATERCAST_PIPE_PORT` | 18000 / 8501 / 8502 | 포트가 겹칠 때 |
| `WATERCAST_NAME` | watercast | 같은 서버에 두 벌 띄울 때(컨테이너 이름 접두) |
| `COMPOSE_PROFILES` | demo | 발표용 데모 화면(8502)이 필요 없으면 비운다 |
| `RUN_AS` | 1000:1000 | 묶음을 푼 계정의 `id -u`:`id -g` 와 **같아야** 탐지 산출물을 쓸 수 있다 |
| `HOST_ROOT` | 비움(=이 디렉터리) | 보통 그대로. 다른 경로에서 compose 를 실행할 때만 이 디렉터리 절대경로 |
| `WBMS_GPU` | auto | GPU 있으면 GPU, 아니면 CPU. GPU 에서 실행이 실패하면 자동으로 CPU 재시도 |
| `KMA_API_KEY` | 비움 | **선택**. 기상청 공공데이터포털 일반 인증키 — 과거 기상 관측·단기예보를 새로 받을 때만. 없어도 예측·탐지·화면 전부 동작 |
| `BACKEND_LIAISON_LOG_URL` / `_SYSTEM_CODE` / `_ALGM_ID` | 비움 / SC000000 / AG000000 | 통합 플랫폼이 알고리즘 로그 주소·코드를 배정하면 채운다. 비어 있으면 로그를 보내지 않는다 |
| `WITH_SMSS_NET` / `SMSS_NET` | 0 / smss-net | 3세부 컨테이너와 같은 도커 네트워크로 직결할 때 1 |

바꾼 뒤 `./start.sh` 로 재기동하면 반영된다.

**데이터 위치(경로를 따로 지정할 필요 없음 — 묶음 디렉터리 기준 고정)**

| 경로 | 뜻 |
|---|---|
| `data/incoming/handover/05_l1_pre/<센서>_pre/<yyyy>/<yyyymmdd>/Pre_Busan_<센서>_<yyyymmdd>T<시각>.tif` | **새 위성 영상(전처리 GeoTIFF)을 넣는 곳**. API 의 `pre_path` 로는 `/app/data/incoming/...` 로 부른다. 업로드(`pre_file`)로 보내면 이 경로가 필요 없다 |
| `data/wbms_runs/wb/<yyyy>/<yyyymmdd>/` | 탐지 결과 마스크(캐시). 묶음에 18장면이 들어 있다 |
| `backend/data/scenes/<지역>/<장면>/` | 장면별 산출(규약 파일 `PT000003_*.tif`, 면적·수위·예측·`level_forecast.json`) |
| `backend/data/wbms_products/` | 통합 플랫폼에 주는 규약 파일명 사본 |
| `backend/data/regions/` | 사용자가 추가·수정한 지역(지점 시계열·학습 모델) |
| `logs/` | 설치·교체·확인 로그와 보고서 |

**키·인증**: 우리 API 에는 인증이 없다. `http://<서버>:18000/api/v1/...` 를 바로 부른다. 위 `KMA_API_KEY` 는 기상청 자료를 새로 받을 때만 쓰는 선택 항목이다.

## 4. 배포 후 확인 (1분)

```bash
./postcheck.sh          # A 환경 · B 설정/디렉터리 · C 컨테이너/포트 · D API · E 스모크 18개 → logs/postcheck_<시각>.txt
./status.sh             # 컨테이너 상태 + health 한 줄
```

`postcheck.sh` 가 보는 것: docker/compose/python3, 디스크 10 GB, `.env`, `app/current` 의 build, 쓰기 디렉터리 5개, 탐지 캐시 장면 수,
RUN_AS 와 산출 디렉터리 소유자 일치, 컨테이너 healthy 와 이미지 태그, 포트 응답, 컨테이너→docker 소켓, wbms 이미지 유무(선택),
API health·버전·build 일치, 지역 목록, 수위 전망 호출, 오류 응답 형식(422 + 한국어 사유 + `X-Request-ID`), 최근 오류 조회, 화면 3개,
서버 오류 로그 0건, 스모크 18개. 실패가 있으면 보고서 끝에 컨테이너 로그 200줄이 붙는다. 종료 코드 0 이면 통과.

브라우저로 볼 주소: `http://<서버>:18000/docs`(API 문서), `/simple`(간단 화면), `/app`(서비스 화면), `/eval`(모델 평가), `http://<서버>:8501/`(업무 UI).

## 5. API 바로 쓰기 (인증 없음)

```bash
S=http://<서버>:18000/api/v1
curl -s $S/health                                                    # 상태·버전·앱 build
curl -s "$S/regions/nakdong_busan/gauge/구포대교/forecast?horizon=7"   # 수위 전망 D+1~7
curl -s -X POST $S/scenes -F region_id=nakdong_busan -F sensor=ICEYE -F image_date=2020-04-16 \
     -F pre_path=/app/data/incoming/handover/05_l1_pre/iceye_pre/2020/20200416/Pre_Busan_ICEYE_20200416T183630.tif \
     -F order_id=21 -F scene_id=5 -F work_id=W-21                     # 장면 파이프라인 접수 → {"scene_id": "20200416_ICEYE", ...}
curl -s $S/scenes/20200416_ICEYE                                     # 진행 상황(단계별 상태·경고)
curl -s $S/scenes/20200416_ICEYE/files/level_forecast.json           # 수위 전망 파일
curl -s "$S/errors/recent?limit=10"                                  # 최근 오류(요청 id·사유)
```
잘못된 입력은 `{"detail": ..., "error": {"status": 422, "message_ko": "입력이 잘못됐습니다: ...", "fields": [...], "request_id": "..."}}` 로 오고,
응답 헤더 `X-Request-ID` 로 `logs/`·`docker compose logs` 에서 같은 요청을 찾는다. 전체 목록과 항목 설명은 `/docs`.

## 6. 코드만 바뀐 앱 바이너리 교체 (1분, 이미지 그대로)

```bash
cp /경로/watercast-app-<버전>-<빌드>.tar.gz* app/      # tar.gz 와 .sha256 둘 다
./update_app.sh app/watercast-app-<버전>-<빌드>.tar.gz  # 체크섬 → app/current 교체(이전은 app/prev) → 재기동 → 헬스 → 스모크
./postcheck.sh --quick
./update_app.sh --rollback                            # 문제 있으면 직전 build 로 되돌림
```
묶음의 `VERSION.json` 에 `runtime_image` 가 있다. 지금 이미지와 다르면(의존성이 바뀐 경우) 새 런타임 이미지도 함께 받아
`images/` 에 넣고 `.env` 의 `WATERCAST_IMAGE` 를 바꾼 뒤 `./install.sh` 를 다시 돌린다 — `update_app.sh` 가 그 경우를 경고한다.

## 6-1. 새 서버(새 세대 GPU)에 처음 올릴 때

호스트 준비(docker·nvidia-container-toolkit)부터 GPU 판정(`./gpu_check.sh`)·첫 장면 시험까지는 `현장_배포_절차.md` 를 따른다. 플랫폼은 GPU 와 무관하고, 탐지만 GPU 가 안 되면 CPU 로 돈다.

## 7. 실패했을 때 보는 곳

| 증상 | 보는 곳 · 대응 |
|---|---|
| 스크립트가 `✘ 실패: <명령> (install.sh N행)` 으로 멈춤 | 그 아래에 로그 파일 경로와 컨테이너 로그 30줄이 찍힌다. `logs/install_*.log` 전체를 보낸다 |
| `호스트 포트 N 가 이미 사용 중` | `.env` 포트 변경 → `./install.sh` 재실행 |
| `3분 안에 API 가 준비되지 않았습니다` | `docker compose logs --tail 200 watercast` — 보통 포트·권한·디스크 |
| 체크섬 불일치 | 전송이 깨진 것. 묶음을 다시 받는다 |
| 탐지 잡 `failed` + `Permission denied: /out` | `.env` RUN_AS 가 `data/wbms_runs` 소유자와 다름 → 맞추고 `./start.sh` |
| 탐지 잡 `failed` + `Cannot connect to the Docker daemon` | compose 의 `/var/run/docker.sock` 줄 확인. 임시로 `./detect_scene.sh <날짜>` |
| GPU 가 있는데 CPU 로 돎 | nvidia-container-toolkit 미설치 또는 VRAM 부족. 잡의 `warnings`/`gpu_fallback` 에 사유. CPU 로도 결과는 같다(10분 내외) |
| API 가 422/404/500 | 응답의 `error.message_ko` 와 `request_id`, `GET /api/v1/errors/recent` |
| 되돌려야 함 | `./update_app.sh --rollback` (앱), `./stop.sh` 뒤 이전 묶음으로 `./install.sh` (전체) |

문의할 때 같이 보낼 것: `logs/` 의 최신 `install_*.log`·`postcheck_*.txt`, `docker compose ps -a`, `cat .env`(키 값은 가려도 됨).
