# 현장 배포 절차 — 새 서버(Ubuntu 24.04 · RTX PRO 5000 · NVIDIA 드라이버 595 · CUDA 13.2)에 패키지로 올리기 (2026-10-25)

대상: 이 패키지를 들고 현장 서버에 처음 설치하는 담당자. 명령은 전부 서버에서 실행한다. `배포_실행순서.md` 가 일반 절차이고,
이 문서는 **현장 GPU 세대가 바뀐 것**(드라이버 595·CUDA 13.2)까지 포함한 처음부터 끝까지의 순서다.

## 0. 먼저 결론 — CUDA 가 바뀌어도 무엇이 영향을 받나

| 구성 요소 | GPU/CUDA 의존 | 현장에서 |
|---|---|---|
| 플랫폼(API·화면·수위 예측·시계열) — `watercast-runtime` 이미지 | **없음**(torch·tensorflow 미포함, numpy 추론) | 그대로 동작 |
| 수체 탐지 이미지 `wbms:0.13`(시립대 인수) | **CUDA 11.8 · cuDNN 8 · TensorFlow 2.14**, 빌드 대상 GPU `sm_35~sm_75 + compute_80(PTX)` | 드라이버 595 는 CUDA 11.8 컨테이너를 구동은 한다(하위 호환). 그러나 RTX PRO 5000(Blackwell, sm_120)용 cuDNN 8 커널이 없어 **GPU 연산이 실패할 가능성이 높다** → 자동으로 CPU 재시도(장면당 10분 내외) |
| 호스트 docker + nvidia-container-toolkit | GPU 를 컨테이너에 넣는 길 | Ubuntu 24.04 에 apt 로 설치. 드라이버 595 와 호환 |

즉 **설치·서비스·예측은 CUDA 와 무관하게 되고, 새 영상 탐지만 GPU 대신 CPU 로 돌 수 있다.** GPU 로 돌리려면 시립대에 CUDA 12.8 이상·cuDNN 9 베이스 재빌드를 받아 이미지만 교체한다(백엔드 수정 없음). `./gpu_check.sh` 가 이 판정을 현장에서 자동으로 내린다.

## 1. 가져갈 것

| 파일 | 크기 | 비고 |
|---|---|---|
| `watercast-<버전>-<날짜>.tar.gz` | 약 40 GB | **패키지 하나** — 플랫폼 런타임 이미지 + 앱 바이너리 + 수체 탐지 엔진(wbms 이미지 11 GB·모델·보조자료) + 전처리 입력 영상 22장 + 스크립트·문서 |
| (선택) docker·nvidia-container-toolkit 설치 파일 | — | 현장에 인터넷이 없으면 `.deb` 를 미리 받아 간다(2절) |

## 2. 호스트 준비 (Ubuntu 24.04, root 또는 sudo, 20분)

```bash
# docker engine + compose v2 (인터넷 있을 때)
sudo apt-get update && sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu noble stable" | sudo tee /etc/apt/sources.list.d/docker.list >/dev/null
sudo apt-get update && sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo usermod -aG docker $USER && newgrp docker          # 재로그인 대신
docker --version && docker compose version

# NVIDIA 드라이버는 이미 595.84 — 그대로 둔다
nvidia-smi --query-gpu=name,driver_version --format=csv

# nvidia-container-toolkit (GPU 탐지를 시도하려면; 안 깔면 탐지는 CPU)
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list >/dev/null
sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker && sudo systemctl restart docker
docker info | grep -i runtimes                          # nvidia 가 보여야 한다

python3 --version; curl --version | head -1            # 3.9+ · curl
df -h /                                                # 90 GB 여유(tar 40 + 풀기 40 + 이미지 12)
```
인터넷이 없는 현장: 위 패키지들의 `.deb`(docker-ce·docker-ce-cli·containerd.io·docker-compose-plugin·nvidia-container-toolkit 과 의존 libnvidia-container*)를 같은 Ubuntu 24.04 에서 `apt-get download` 로 받아 가서 `sudo dpkg -i *.deb`.

## 3. 패키지 설치 (30분, 탐지 엔진 이미지 적재 포함)

```bash
mkdir -p ~/watercast && cd ~/watercast
tar -xzf /media/usb/watercast-<버전>-<날짜>.tar.gz && cd watercast-<버전>-<날짜>     # 40 GB, 수 분
cp .env.example .env
# 꼭 볼 항목: RUN_AS=$(id -u):$(id -g)  · 포트가 비어 있으면 18000/8501/8502 그대로 · WBMS_GPU=auto 그대로
# 선택: KMA_API_KEY(기상청 자료 새로 받을 때만), BACKEND_LIAISON_*(통합 플랫폼 배정값)
./install.sh            # 7단계(런타임·탐지 엔진 이미지 적재 포함, 탐지 이미지 11 GB 는 10분 이상), 끝에 스모크 18개. 로그 logs/install_<시각>.log
./postcheck.sh          # 30개 점검 보고서 logs/postcheck_<시각>.txt — "결과: 통과 N · 실패 0" 이면 OK
```
여기까지로 API(`http://<서버>:18000/docs`)·간단 화면(`/simple`)·업무 UI(8501)·수위 예측·탐지 엔진까지 다 올라간다.

## 4. GPU 판정 (5분)

```bash
cd ~/watercast/watercast-<버전>-<날짜>
./gpu_check.sh                  # 1 호스트 드라이버 → 2 툴킷 → 3 컨테이너 안 GPU → 4 TF 인식 → 5 합성곱 실험 → 판정
```
`gpu_check.sh` 의 판정에 따라:

| 판정 | 뜻 | 할 일 |
|---|---|---|
| `GPU 로 돌릴 수 있습니다` | 새 GPU 에서도 CUDA 11.8 이미지가 돈다 | `.env` 그대로(`WBMS_GPU=auto`). 장면당 30~60초 |
| `탐지는 CPU 로 돕니다 … GPU 커널 실행 실패` | **예상되는 경우.** 이미지의 cuDNN 8 이 Blackwell 커널이 없음 | 그대로 운영해도 된다(auto: GPU 시도 뒤 CPU 재시도, 장면당 10분 내외). 매번 시도가 아까우면 `WBMS_GPU=cpu` 로 고정하고 `./start.sh`. 시립대에 **CUDA 12.8 이상·cuDNN 9 베이스 재빌드**(예: NGC TensorFlow 25.03 이상) 요청 → 받은 이미지를 `docker load` 하고 `.env` `BACKEND_WBMS_IMAGE`(패키지 compose 는 wbms:0.13 고정이므로 새 태그를 wbms:0.13 으로 `docker tag`) 뒤 `./gpu_check.sh` 재실행 |
| `TF 가 GPU 를 인식하지 못함` / `docker --gpus 실패` | 툴킷·드라이버 쪽 문제 | 2절의 toolkit 설치·`nvidia-ctk runtime configure`·docker 재시작 확인 |
| `호스트 드라이버 없음` | GPU 없음 | CPU 운영 |

GPU 판정과 무관하게 **첫 실제 장면으로 한 번 돌려 본다**:
```bash
# 전처리 영상을 입력 위치에 둔다 (없으면 묶음에 든 2020-04-16 부산 ICEYE 로 시험)
S=http://127.0.0.1:18000/api/v1
curl -s -X POST $S/scenes -F region_id=nakdong_busan -F sensor=ICEYE -F image_date=2020-04-16 -F acquisition_time=183630 \
  -F pre_path=/app/data/incoming/handover/05_l1_pre/iceye_pre/2020/20200416/Pre_Busan_ICEYE_20200416T183630.tif -F detect=true
curl -s $S/scenes/20200416_ICEYE | python3 -c 'import sys,json; d=json.load(sys.stdin); [print(s["key"], s["status"], (s.get("detail") or "")[:80]) for s in d["steps"]]; print("warnings", d.get("warnings"))'
```
`detect` 단계 detail 에 `컨테이너 NN s` 가 60초 안쪽이면 GPU, 수 분이면 CPU 다. 결과 `warnings`/`gpu_fallback` 에 CPU 재시도 사유가 남는다.

## 5. 통합 플랫폼 연계 값·네트워크 (세명소프트·1세부와 맞춘 뒤)

```bash
vi .env      # BACKEND_LIAISON_LOG_URL / _SYSTEM_CODE / _ALGM_ID, 필요하면 WITH_SMSS_NET=1 · SMSS_NET=<네트워크 이름>
./start.sh   # 재기동으로 반영
./postcheck.sh --quick
```
외부에서 부르는 주소는 `http://<서버>:18000/api/v1/...`(인증 없음). 같은 도커 네트워크(smss-net)에 붙였으면 `http://watercast:8000/api/v1/...`.

## 6. 이후 운영

| 상황 | 명령 |
|---|---|
| 코드만 바뀐 배포 | `cp watercast-app-<버전>-<빌드>.tar.gz* app/ && ./update_app.sh app/watercast-app-<버전>-<빌드>.tar.gz` (1분, 이미지 그대로) · 되돌리기 `./update_app.sh --rollback` |
| 탐지 이미지 교체(재빌드본) | `docker load -i <새 이미지.tar.gz> && docker tag <새 태그> wbms:0.13 && ./gpu_check.sh` |
| 상태·재기동·중지 | `./status.sh` · `./start.sh` · `./stop.sh` |
| 확인 | `./postcheck.sh` (보고서 `logs/`) · `./smoke_test.sh` |
| 제거 | `./uninstall.sh --images [--wbms-image] [--data]` |

## 7. 실패 시 보낼 것

`logs/` 의 최신 `install_*.log` · `postcheck_*.txt` · `gpu_check_*.log`, `docker compose ps -a`, `nvidia-smi` 출력, `cat .env`(키 값은 가려도 됨). 스크립트는 실패한 명령·줄·컨테이너 로그 30줄을 화면 마지막에 찍으니 그 부분을 그대로 캡처해도 된다.
