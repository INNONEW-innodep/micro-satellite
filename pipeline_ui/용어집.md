# 📚 발표용 용어집

발표에 나오는 모든 약어·전문용어를 카테고리별로 정리. 누가 물으면 이걸 보고 답하면 됩니다.

## 🛰️ 1. 위성·원격탐사 용어

| 용어 | 영문 | 쉬운 설명 |
|---|---|---|
| **SAR** | Synthetic Aperture Radar | 합성개구레이더. **레이더 전파를 쏘아서 반사된 신호로 영상을 만듦**. 구름·밤에도 촬영 가능. (광학과 정반대) |
| **광학 위성** | Optical satellite | 일반 카메라처럼 **태양빛 반사를 받는 위성**. 구름 끼면 못 찍음 |
| **ICEYE** | — | 핀란드 회사의 **SAR 초소형 위성**. X-band (파장 3cm) 사용. 우리 입력 위성 중 하나 |
| **PlanetScope** | — | 미국 Planet 사의 **광학 초소형 위성**. 3m 해상도. 우리 입력 위성 중 하나 |
| **TerraSAR-X** | — | 독일의 큰 SAR 위성. 이전(2차년도)에 쓰던 위성. 지금은 ICEYE로 변경됨 |
| **Stripmap** | — | SAR 촬영 모드 중 하나. **일정한 폭으로 길게 띠 모양으로** 찍음 |
| **SLC** | Single Look Complex | SAR 원본 데이터. **실수+허수 복소수**로 구성. 그대로는 영상이 안 보임 |
| **Intensity Image** | — | SLC 복소수를 **크기(절대값)로 바꾼 영상**. 비로소 영상으로 보임 |
| **Sigma0 (σ₀)** | Backscatter coefficient | 후방산란계수. **물체가 레이더 신호를 얼마나 되돌려주는지** 수치화. 물=낮음, 도시=높음 |
| **Decibel(dB) 변환** | — | Sigma0를 로그(log)로 변환. **Rayleigh 분포 → 정규분포**로 만들어 분석 쉽게 함 |
| **Multi-Look** | — | 노이즈 줄이기 위해 **여러 픽셀을 평균**내는 SAR 전처리 |
| **정사보정 / Orthorectification** | — | 위성 영상을 **지도와 정확히 맞춰주는** 작업. 지형 굴곡 보정 포함 |
| **Geocoding** | — | 영상의 픽셀에 **위경도 좌표를 입혀주는** 작업 |
| **DEM** | Digital Elevation Model | **수치표고모델**. 땅의 높이 정보. 우리는 수위 추정과 침수 시뮬레이션에 사용 |
| **AOI** | Area of Interest | 관심 영역. **분석할 지리적 범위**를 좌표(top_left, bottom_right)로 지정 |
| **GeoTIFF** | — | **지리 좌표가 포함된 TIFF 영상**. 우리 모든 입출력 영상의 표준 포맷 |
| **EPSG:32652** | — | 좌표계 코드. **UTM Zone 52N** (한국 동부) 의미 |
| **궤도 ASC/DSC** | Ascending / Descending | 위성이 적도를 **북상하며(ASC) / 남하하며(DSC)** 찍은 영상. 보정 방식이 다름 |
| **재방문주기** | Revisit Interval | 같은 지역을 다시 찍는 데 걸리는 시간. ICEYE는 약 11일 |
| **Layover / Shadow** | — | SAR 영상의 **기하학적 왜곡**. 산이 누워보이거나 그림자가 생김. 보정 필요 |

## 🤖 2. 머신러닝·딥러닝 용어

| 용어 | 영문 | 쉬운 설명 |
|---|---|---|
| **세그멘테이션** | Semantic Segmentation | **픽셀 단위로 분류**. "이 픽셀은 물/저 픽셀은 땅" 식. 우리는 "수체/비수체" 2-class |
| **U-Net** | — | 의료영상·위성영상 세그멘테이션에 많이 쓰는 **CNN 모델**. U자 모양 구조 |
| **CNN** | Convolutional Neural Network | 이미지 처리에 특화된 **합성곱 신경망** |
| **ConvLSTM** | Convolutional LSTM | **CNN + LSTM 결합**. 영상의 공간 정보 + 시간 변화를 같이 학습. 우리 시계열 예측 모델 |
| **LSTM** | Long Short-Term Memory | **순환 신경망(RNN) 의 한 종류**. 시계열 데이터에 강함 |
| **Encoder-Decoder** | — | **인코더**: 입력을 압축 / **디코더**: 다시 복원. 우리 모델 구조 |
| **Feature Fusion** | — | 두 가지 정보(영상 + 기상)를 **하나로 결합**해 모델에 넣는 기법 |
| **Autoregressive** | 자기회귀 | 직전 예측값을 **다시 입력으로 넣어 다음을 예측**. 시계열 연장 기법 |
| **Patch / 패치** | — | 큰 영상을 작은 조각(512×512)으로 자른 것. **메모리 절약 + 데이터 증강** |
| **Overlap 25%** | — | 패치 자를 때 **25% 겹치게** 자름. 경계 부분 학습 잘 되라고 |
| **Min-Max 정규화** | — | 픽셀 값을 [0, 1] 사이로 **스케일 조정** |
| **Class Weights [0.15, 0.85]** | — | 수체(0=배경, 1=수체)가 **불균형**해서 수체에 가중치 0.85, 배경에 0.15 |
| **Loss / 손실 함수** | — | 모델이 **얼마나 틀렸는지** 점수화. 낮을수록 좋음 |
| **BCE + Dice Loss** | — | **이진교차엔트로피 + Dice 손실**의 결합. 세그멘테이션 표준 조합 |
| **Adam** | — | 가장 많이 쓰는 **최적화 알고리즘** (Optimizer) |
| **Learning Rate (lr)** | — | **학습 속도**. 너무 크면 발산, 너무 작으면 수렴 안 됨 |
| **Batch Size** | — | 한 번에 학습에 넣는 **샘플 개수** |
| **Epoch** | — | 전체 데이터를 **한 바퀴 돌리는 단위** |
| **Early Stopping** | — | **검증 손실이 개선 안 되면 멈춤**. 과적합 방지 |
| **patience=10** | — | "10 epoch 동안 안 좋아지면 멈춤" 의미 |
| **ReduceLROnPlateau** | — | **손실이 정체되면 학습률 자동 감소** |
| **Mixed Precision** | — | float32와 **float16을 섞어 학습**. **메모리 절감 + 속도 향상** |
| **Hold-out** | — | 일부 데이터를 **건드리지 않고 최종 평가용**으로 빼둠 |
| **Overfitting / 과적합** | — | 학습 데이터만 외워서 **새 데이터에는 못 맞춤** |
| **KNN Imputer** | — | 결측치(missing)를 **이웃 픽셀 값들로 채워주는** 기법 |
| **Shifted Frames** | — | (T1, T2, T3)→(T2, T3, T4) 식으로 **한 칸씩 밀어** 입력/출력 페어 만들기 |

## ❓ 자주 헷갈리는 부분

### Q. 우리 입력은 어디서 오나?
- **1세부(수자원공사/인하대)** 가 ICEYE/PlanetScope 위성 영상을 수집해 우리에게 줍니다.

### Q. 우리(2세부)는 어디까지 하나?
- 4단계 시스템 (전처리 → 탐지 → 수위/면적 → 퓨전) + **★ 이노뎁의 시계열 예측 모델**
- 최종 산출(CSV/XML/GeoTIFF)을 **3세부**에 전달

### Q. 시립대(같은 2세부)와 이노뎁 역할 구분?
- 4단계 시스템 = 공동 영역
- **★ 시계열 예측(ConvLSTM) + 작물 분류 = 이노뎁만 함**

### Q. SAR vs 광학 차이?
| | SAR (ICEYE) | 광학 (PlanetScope) |
|---|---|---|
| 원리 | 레이더 전파 | 태양빛 반사 |
| 구름 | 뚫음 ✅ | 못 뚫음 ❌ |
| 밤 | 가능 ✅ | 불가 ❌ |
| 해상도 | 0.5~1.5m | 3m |
| 색상 | 흑백 (강도) | RGB |
| 수체 식별 | 어둡게 보임 | 색으로 식별 |

### Q. ConvLSTM이 왜 좋은가?
- **CNN**: 한 장의 영상 분석에 강함
- **LSTM**: 시간 순서가 있는 데이터에 강함
- **ConvLSTM**: 둘 다 합쳐서 → **위성 영상 시계열 변화 학습**에 딱

### Q. 왜 기상 데이터를 같이 쓰나?
- 수체 변화는 **강수·기온·증발**과 직접 관련됨
- 영상만 보면 "왜 줄었는지" 모르지만, 기상까지 보면 **원인 파악 + 예측 정확도 향상**

### Q. IoU 0.926 은 어느 수준?
- **0.7 이상 양호, 0.9 이상 매우 우수**. 0.926 이면 **거의 실용 상용 수준**.
- 우리 실측(배포 프로토콜, VALREPORT JSON): SAR 0.926 / 광학 0.942. 두 센서 모두 매우 우수.

### Q. 왜 융합 LSTM 을 "향상" 이 아닌 "보정기" 로 소개하나?
- LODO 검증에서 위성 없는 베이스라인 RMSE (0.020m) 가 융합보다 낮게 나옴
- 그래서 **위성 융합이 곧 향상은 아니고**, 게이지 기반 보정기 역할로 위치시킴
- 확장 검증(다지역, 다기간)에서 우위가 확인되면 그때 "향상" 표현 가능

### Q. GPU 도입으로 얼마나 빨라지나?
- **SAR 씬당 499초 → 42.8초 (약 11.7배 가속)**
- 씬당 1분 미만이 되어 관제 시나리오 가능성 열림
- 조건: 공유 GPU 3GB 여유. 광학 모델은 VRAM 부족 시 CPU 자동 폴백

### Q. 시계열 예측 모델 정확도는?
- **실측 확보 완료** (부산 갈수기)
  - **수위 RMSE 2.3~2.5 cm** (지평 1~58일, 99쌍) — 목표 대비 ×15 정확
  - **수체 IoU 0.78~0.90** (12쌍, 단기·장기 평균 ≈ 0.84)
- 근거: `data/eval/timeseries_metrics.json`, `mask_persistence_iou.json`
- 각주 필수: **부산 갈수기 조건. 홍수기 급변 저하는 별도 검증 필요**

### Q. IoU 가 지평 길어져도 왜 안 떨어지나?
- **부산이 갈수기라 수체 자체 변화가 작음**
- **예측 IoU ≈ 변화 상한 IoU** (12쌍 모두 차이 ≤ 0.01)
- → 오차의 지배 요인은 마스크 품질이 아니라 **수체 자체 변화**
- 홍수기·급변 시나리오에서는 다를 수 있음

### Q. G 계열 (성과지표 정합값 0.135) 은 뭐고 왜 F 보다 중요한가?
